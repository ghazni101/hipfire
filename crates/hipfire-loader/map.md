# hipfire-loader — map

> **Status:** `production` (vocabulary owned by [`docs/GLOSSARY.md`](../../docs/GLOSSARY.md)).
> **Layer:** Composition root — top of the DAG's load path, above `hipfire-runtime`; arch crates hang off it via `Carrier`; see the layering table in [`docs/ARCHITECTURE.md`](../../docs/ARCHITECTURE.md) and the carrier table in [`docs/architecture-ids.md`](../../docs/architecture-ids.md).

## Purpose

Single `load_model` dispatch for the daemon. Owns `LoadedModel` / `ModelState` closed enum, the object-safe `Carrier` trait and `REGISTRY` in [`src/carriers.rs`](src/carriers.rs) / [`src/lib.rs`](src/lib.rs) (impls stay in `carriers.rs` because `Carrier::load` returns `LoadedModel` and arch crates must not depend on the loader), `ModelSource::from_path` source × carrier routing (HFQ vs `SafetensorsSource` dir, `UNCLAIMED_ARCH_ID` sentinel), `batch_staging`, and `spec_build` RAII glues. Arch-agnostic callers destructure only via `as_arch_model{,_mut}`.

## Gotchas

- `load_model` requires exactly one matching carrier (0 → error; 2 → ambiguous) — add a carrier only after reserving its `arch_id` in `docs/architecture-ids.md`.
- Per-arch load bodies now live in the arch crates as `load_<arch>_bundle(src, ctx)`; `carriers.rs` is the thin registry that calls them — do not pull weight/config parsing back into the loader.
- `LoadedModel.ep` holds expert-parallel rank state separately from `state`; EP staging reclaims completed ranks on failure but a mid-constructor failure can leak that rank's partial allocs.
- The Qwen4 carrier reads `memory.session_cache_bytes` once at load and, when it is above 0, attaches the engine-owned session cache (keyed by the model's `CacheDomain`) to the bundle after the native MTP head is built, logging `qwen4 session cache: N MiB budget, N MiB per C-token snapshot; snapshots yield to context growth`. `0` attaches nothing, which also disables the bundle's live continuation; no prefix/radix cache is attached any more.
- The Qwen4 carrier opens the PLE hot-row store (`memory.ple_hot_store_bytes` / `HIPFIRE_PLE_HOT_STORE_BYTES`, default `0` = off) before the weight sweep (`start_ple_hot_store`). It needs unified memory, Q8F16 PLE shards, the `<model>.plehot` sidecar and the `<model>.plehotrows` pack (paths overridable via `HIPFIRE_PLE_HOT_RANK_FILE` / `HIPFIRE_PLE_HOT_PACK_FILE`). Its worker verifies the pack against the model during the load; the row store reads the pack's rows from the pack once verified. After admission and session-cache attach, the carrier sets the prewarm budget (`ple_hot_prewarm_budget`): an explicit N, or `auto` = `MemAvailable` − `PLE_HOT_PREWARM_RESERVE_BYTES` (4 GiB). The worker then reads that much of the pack into the page cache (hottest tier first, then tier 0 a second time to promote it to the active list) while no PLE fetch ran for 5 s. Nothing is charged to admission: the pack is reclaimable page cache.
- With a rank-ordered q4 PLE table (`<model>.ple-q4`), the Qwen4 carrier starts the table's worker before the weight sweep (`start_ple_table_worker`): it reads the table's hottest prefix into the page cache at ≤ `PLE_LOAD_FILL_BYTES_PER_SEC` (0.2 GB/s) while the weights load, and re-reads pages of the prefix the weight file's cache traffic evicted, hottest first (`HotRowStore::load_fill`, `mincore` view). Size: `memory.ple_load_fill_bytes` / `HIPFIRE_PLE_LOAD_FILL_BYTES` (`auto` = `PLE_LOAD_FILL_AUTO_BYTES`, 14 GiB; `0` = off), capped by `ple_load_fill_bytes` at the table, an explicit `memory.ple_prewarm_bytes`, and `uma_memory::host_available_bytes` (`MemAvailable` + TTM pool: a previous process's freed GTT pages sit in the pool, outside `MemAvailable`) minus the weights the load puts in host RAM (unified memory: every non-external weight; discrete: host-mapped experts) minus `PLE_PREWARM_RESERVE_BYTES`; logged as `qwen4 ple load fill: …`. At ready the carrier sets the prewarm budget (`ple_prewarm_budget`), which ends the fill (ready never waits for it); the idle prewarm continues at the end of the resident prefix, and the worker is attached to the bundle (`attach_ple_table_worker`).
- Qwen4 context admission (unified-memory archs only; a discrete GPU keeps `QWEN4_DEFAULT_CONTEXT` and no sequence): an omitted `max_seq` resolves in `admission.rs` to a pending sequence at the model context (VMM only). After every load allocation the carrier measures free device memory (`Gpu::device_mem_info`) and runs `admission::qwen4_memory_admission` (target+MTP QSA growth, gather workspace, MTP request buffers, `QWEN4_MEMORY_HEADROOM_BYTES`), logging `qwen4 memory admission: …; card_cap N tokens`. Automatic contexts take `min(model_ctx, card_cap)`; an explicit `max_seq` that cannot grow refuses at load (warns with `memory.oom_guard` off). The session cache is never charged. Before allocating, a unified-memory fully resident load refuses (guard on) when weights + reserve exceed that free figure.
- Every free-memory sizing site uses `Gpu::device_mem_info`, never `hip.get_vram_info` directly: on a GTT-backed APU it clamps `hipMemGetInfo` free to `MemAvailable` + TTM pool (`rdna_compute::uma_memory`).
